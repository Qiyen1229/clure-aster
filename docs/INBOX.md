# 自動記帳收件匣（iPhone 捷徑）

收件匣是「記帳專用的信箱」：iPhone 的捷徑 App 在你付款或收到通知時，自動把內容寄到你自己的伺服器；打開 Clure 確認一下就記好帳。

```
Apple Pay 付款／銀行簡訊／對 Siri 說一句話
        │  iPhone 捷徑（自動化）
        ▼
POST https://你的網址/api/hook/inbox   ← 捷徑專用權杖（只能寄、不能讀帳）
        │  伺服器暫存
        ▼
打開 Clure → 解析成帳目 → 確認記帳（或自動入帳）→ 從伺服器刪除
```

## 1. 建立捷徑權杖

App →「設定 → 自動記帳收件匣 → 建立捷徑權杖」。畫面會顯示：

| 項目 | 內容 |
|---|---|
| 網址 | `https://你的網址/api/hook/inbox` |
| 標頭值 | `Bearer clr_…`（只顯示這一次，請直接複製到捷徑） |

可以按「傳送測試項目」確認連得到。權杖遺失或手機換掉時，撤銷舊的再建一組即可。

## 2. 三種捷徑

三種捷徑的共同動作都是「**取得 URL 的內容**」：

- 網址：上面的網址
- 方法：`POST`
- 標頭：`Authorization` ＝ 標頭值（`Bearer clr_…`）
- 要求本文：`JSON`，欄位類型都選「文字」

### Apple Pay 付款後自動記帳（iOS 17 以上）

捷徑 →「自動化」→「＋」→「交易」→ 選卡片 →「立即執行」→ 新增空白自動化，加入上面的動作：

| 欄位 | 值 |
|---|---|
| `source` | `applepay` |
| `amount` | 捷徑輸入 → 金額 |
| `merchant` | 捷徑輸入 → 商家 |
| `card` | 捷徑輸入 → 卡片或票證 |

### 銀行刷卡簡訊

「自動化」→「＋」→「訊息」→ 寄件者選銀行，或「訊息包含」填「消費」→「立即執行」：

| 欄位 | 值 |
|---|---|
| `source` | `sms` |
| `text` | 捷徑輸入 → 內容 |

### 對 Siri 說一句話

新增捷徑，名稱「記一筆」→ 動作「聽寫文字」（中文（台灣））→ 取得 URL 的內容：

| 欄位 | 值 |
|---|---|
| `source` | `siri` |
| `text` | 聽寫的文字 |

說「嘿 Siri，記一筆」，再說「昨天午餐 150 刷玉山卡」或「早餐 60 午餐 120」。

## 3. App 怎麼判斷

- **金額**：Apple Pay 的金額欄位；簡訊找「NT$」「元」後面的數字（不會把卡號末四碼當金額）
- **日期**：簡訊或 Siri 內容裡的日期（10/27、昨天）；沒有就用收到的時間
- **帳戶**：學過的「卡片 → 帳戶」→ 文字裡的帳戶名稱 → 自動分類規則指定的帳戶 → 同一個商家最常用的帳戶 → 收件匣預設帳戶
- **分類**：自動分類規則 → 商家記憶 → 文字裡的分類名稱 →「其他」
- 確認記帳時會記住「這張卡 → 這個帳戶」，可在收件匣頁面修改

## 4. 安全與隱私

- 權杖只能「寄」，不能讀取任何帳目；伺服器只存 SHA-256 雜湊，可隨時撤銷
- `/api/hook/inbox` 不使用登入 Cookie，所以不需要 CSRF；每組權杖每分鐘最多 30 則，錯誤權杖以 IP 限制
- 暫存內容**沒有端對端加密**（捷徑沒有你的加密密碼）；確認或略過後立即刪除，30 天未處理自動清除
- 兩台裝置同時確認同一則，只有一台會記帳

## 5. 常見問題

- **外出時捷徑失敗**：網址要用 NAS 的外部 HTTPS 網址；外層有 Cloudflare Access 等登入保護時，需放行 `/api/hook/`
- **Apple Pay 沒觸發**：iOS 17 以上才有「交易」自動化；部分卡片、交通卡不會觸發
- **送來空白或被拒絕的交易**：預設先放收件匣等你確認，可以按「略過」；確定都正確後再開「看得懂的直接記帳」
- **銀行改用 App 推播**：iPhone 無法讀取其他 App 的推播，只能用簡訊或 Apple Pay
