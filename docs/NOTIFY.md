# 外部通知：Discord／Telegram／LINE／Webhook

異常大額、預算超支、週報月報、發票中獎…直接推到你的聊天軟體。**由你自己的伺服器發送**，App 沒開也收得到週報與繳款提醒。

App →「設定 → 外部通知」（需要伺服器版）。

```
App 偵測到事件（異常大額、預算超支、發票中獎…）──┐
                                                  ├→ POST /api/notify/event ─┐
排程提醒（週報、月報、繳款、訂閱…，由 App 排好）──→ 伺服器背景迴圈到點 ──────┤
                                                                              ▼
                                          你勾選了這類通知的通道（Discord／Telegram／LINE／Webhook）
```

> 逐步設定教學（含常見問題）也直接放在 App：設定 → 外部通知 → 設定教學；內容在 `src/features/settings/channelGuides.ts`。

## 通知類型

每個通道各自勾選要收哪些：

| 類型 | 內容 | 預設 |
|---|---|---|
| 異常與漲價 | 異常大額、訂閱漲價偵測的新結果 | ✅ |
| 預算 | 預算預警、超支 | ✅ |
| 週報／月報 | 每週、每月摘要出爐（排程，App 沒開也會送；標題為主，不含金額） | ✅ |
| 發票中獎 | 統一發票對中獎（領獎期間內） | ✅ |
| 提醒 | 信用卡繳款、訂閱續約、心願冷靜期、備份、到價 | — |
| 每日記帳 | 今天還沒記帳（較頻繁，預設不開） | — |

同一件事在兩台裝置各偵測到一次，伺服器用去重鍵確保 24 小時內只轉送一次。

## 各平台怎麼設定

- **Discord**：頻道設定 → 整合 → Webhook → 新 Webhook，複製「Webhook 網址」。建議開只有自己或家人的頻道；網址等於發言權限，外流請直接刪除重建。訊息是一張彩色卡片（顏色依嚴重程度）。
- **Telegram**：找 @BotFather 傳 `/newbot` 取得「Bot 權杖」；對你的機器人（或把它加進群組）傳一則訊息，開 `https://api.telegram.org/bot<權杖>/getUpdates` 找到 chat 的 `id`（群組是負數）。
- **LINE**：LINE Notify 已在 2025 年 3 月終止，改用 LINE 官方帳號的 Messaging API：到 LINE Developers 建立 Messaging API 頻道，簽發「Channel access token（長期）」，「Your user ID」就是接收對象（先把官方帳號加為好友）。訊息是一張 Flex 卡片，附「在 Aster 開啟」按鈕。
- **自訂 Webhook**：任何接受 JSON POST 的網址（n8n、Make、Home Assistant、自己的程式）。內容：

  ```json
  { "app": "aster", "event": "budget", "level": "warn", "title": "…", "body": "…",
    "url": "https://你的網址/plan", "fields": [{ "name": "已用", "value": "$9,200" }] }
  ```

  填了「簽章密鑰」會在標頭附 `X-Aster-Signature: sha256=<HMAC-SHA256(密鑰, 請求本文)>`，接收端可驗證確實是你的 Aster 送的。

「在 Aster 開啟」的連結需要在 `.env` 設定 `CLURE_PUBLIC_URL`（站內路徑才會變成連結，外部網址一律不附）。

## 安全設計

| 風險 | 作法 |
|---|---|
| 機密外流（網址、權杖） | 以 AES-256-GCM 加密後才存進資料庫（金鑰由伺服器 JWT 金鑰經 HKDF 導出）；列表只回遮罩後的提示；錯誤訊息一律遮掉權杖，日誌不記錄內容 |
| SSRF：伺服器被拿去探測內網 | Discord／Telegram／LINE 只連官方固定網域，網址由程式組出；自訂 Webhook 只允許 https、不允許帳密、只能 443 埠、不跟隨轉址，而且網域解析出的**每個 IP 都必須是公開位址**（擋掉內網、本機、`169.254.169.254` 雲端中繼資料）；發送當下再檢查一次 |
| 被拿來洗頻 | 事件每人每分鐘 20 則、新增與測試每分鐘 6 次、每人最多 10 個通道 |
| 單一通道拖垮其他通道 | 同時發送、各自 8 秒逾時，失敗原因記在該通道上（畫面顯示 ❌） |
| 內容外洩到聊天軟體 | 「訊息包含金額與名稱」可關閉，關閉時只送通用標題；啟用端對端加密時請務必斟酌（訊息會經過第三方伺服器） |

想通知內網服務：在 `.env` 設定 `CLURE_NOTIFY_ALLOW_PRIVATE=true`（允許 http 與內網位址；請確認只有信任的人能登入）。

## 已知限制

- 排程提醒（週報、月報、繳款…）是 App 在開啟時算好交給伺服器的；至少開啟過 App 一次、且通道已開啟才會排程。
- 異常偵測、預算預警是 App 端判斷，所以需要 App 開啟過才會觸發（這些判斷用到你的帳目，伺服器看不到，尤其是端對端加密時）。
- 通道設定存在伺服器；伺服器的 JWT 金鑰（`data/jwt_secret`）遺失或更換後舊設定無法解密，請刪除重建。
