# AI 功能（選用）

Aster 2.0 把 AI 放進記帳的各個環節。**管理員共用一把 Key，每位使用者有每日／每週／每月免費額度**；AI 失敗或看不懂時不扣額度；規則能處理的事一律先用規則（本機、免費、離線）。

## 功能一覽

| 功能 | 在哪裡 | 送給 AI 的內容 | 額度 |
|---|---|---|---|
| **一句話／語音記帳後備** | 記帳面板、語音彈窗 | 你輸入的那一句話、分類與帳戶**名稱** | 1 點，只有規則找不到金額時才用 |
| **問 AI** | AI 助理（`/ai`）、搜尋頁「問 AI」 | 問題＋去識別化收支統計；有持股時另附**投資與稅務統計**（持股市值與未實現損益合計、即將除息的股票代號與預計配息／二代健保、海外所得與門檻比例，全是整數元，無股數與成本） | 1 點 |
| **規劃預算** | AI 對話框（「依過去 3 個月的花費幫我設定各分類預算」）、預算頁按鈕 | 由操作助手規劃（見下方「操作助手」）；先預覽、確認才建立、7 天內可還原 | 1 點 |
| **白話解讀** | 週報／月報頁、AI 助理 | 該期分類層級統計 | 1 點 |
| **整理分類** | AI 對話框（「把『其他』分類的帳目重新分類」） | 由操作助手規劃；先預覽、確認才執行、7 天內可還原 | 1 點 |
| **拍照記帳（可批次）** | AI 對話框 📷（一次最多 8 張，逐張辨識、同一張草稿卡一次記帳；超過 2 張先確認額度） | 縮小後的收據照片（長邊 1280px、約 250KB）＋分類名稱 | 2 點 |
| **專案／帳戶解說** | 專案詳情、帳戶詳情、報表頁（月） | 該專案／帳戶的去識別化統計 | 1 點 |
| **收件匣 AI 解析** | 收件匣中「看不懂金額」的項目 | 那則簡訊／通知文字（**先去掉網址、身分證、卡號、連續 10 碼以上數字**） | 1 點；只有按下按鈕才送 |
| **新支出的市價檢查**（系統自動、可關閉） | 新增支出時自動 | 規則判斷不了的那一筆：分類名稱、備註（先去掉網址與長數字）、金額、幣別、日期、你這個分類平常一筆約多少 | **不計額度**；每筆只問一次、不能手動重跑；管理員總開關與全站每分鐘上限仍有效 |
| **操作助手（用說的整理帳本）**（v4.0） | AI 助理頁最上面；首頁對話框說出「要整理帳本」的話會轉過去 | 你說的那一句話、分類與帳戶**名稱**（不送任何帳目） | 1 點；AI 只規劃，**先預覽、你確認才執行、7 天內可一鍵還原**（見下） |
| **帳單截圖對帳**（v4.0） | 設定 → 匯入 CSV →「對帳」→ 帳單截圖 | 縮小後的帳單截圖（長邊 2000px、約 0.9MB，不保存在伺服器） | 每張 2 點；明細加總會和帳單合計驗證，比對與補帳在本機完成 |
| **首頁上週重點**（選用） | 首頁 | 上週的分類層級統計 | 每週最多自動 1 點，需另外開啟 |

- **去識別化收支統計**（由 `src/domain/aisummary.ts` 整理，有單元測試）：最近約 6 個月每月的收入、支出與各分類合計（分類最多 10 個，其餘併為「其餘分類」）、每月固定支出（訂閱／週期／分期／貸款）、各預算的上限與已花、存錢目標進度、淨資產，**金額一律為整數**。**不包含**：單筆帳目、備註、商家、日期明細、帳戶名稱、標籤。
- **三個開關，預設都關**（「設定 → AI 設定」）：「啟用 AI 功能」（句子、備註、照片、搜尋描述）、「允許 AI 分析我的收支統計」（統計類），以及「首頁自動顯示上週重點」（每週自動 1 點）。
- **結果快取在這台裝置**（`meta` 表，不同步）：相同資料＋相同問題在 6～24 小時內直接顯示舊結果，不呼叫、不扣額度；同一個請求進行中時重複觸發會共用同一次結果。
- AI 的輸出一律當**純文字**顯示，並經過伺服器端驗證（型別、範圍、分類必須在你的名單內），不合格的欄位丟棄。提示詞把使用者文字與統計都視為資料，不是指令。

## 隱私

- 內容會經過**你的伺服器**與**第三方 AI 供應商**，不在端對端加密範圍內。伺服器不保存內容，日誌與 `ai_usage` 只記次數、功能、供應商與模型。
- **Google Gemini 免費層：內容可能被 Google 用來改進產品**（付費層不會）。其他免費模型同理，請不要在輸入裡寫入敏感資料。要避免，請改用付費方案，或不要開啟 AI。

## NAS 上線步驟（熱更新版）

1. **電腦上打包**：在專案資料夾執行 `npm run pack:nas`，產生 `aster-nas.zip`（不含 `.env` 與 `data/`）。
2. **覆蓋到 NAS**：解壓縮後覆蓋到 NAS 上同一個專案資料夾（**不要先刪除資料夾**）。`web-builder` 會自動重新建置前端（約 30–90 秒），後端自動熱重載並套用遷移。
3. **編輯 NAS 上的 `.env`**，至少填一把 Key（變數說明見 `.env.example`）。以 Gemini 為例：
   ```
   CLURE_AI_PROVIDERS=gemini
   CLURE_AI_GEMINI_API_KEY=你的GeminiKey
   ```
   - Key 申請：https://aistudio.google.com/apikey（免費、不用信用卡）。
   - 其餘變數都有預設值，不用寫。**舊版（1.5.x）用 `CLURE_AI_CUSTOM_*` 接 Gemini 的設定仍然可用**，不必改。
4. **套用設定**（`docker-compose.yml` 有新增變數，必須重建 api 容器；不要刪除專案）：
   ```bash
   sudo docker compose -p 專案名稱 up -d
   ```
   Container Manager 建立的專案，名稱以 `sudo docker inspect clure-api --format '{{ index .Config.Labels "com.docker.compose.project" }}'` 查詢。
5. **確認 Key 有效**（建議 A）：
   - **A. App 內**：管理員 →「資安後台 → AI 主控台」→「全部測試」。綠燈＋毫秒數＝Key、網址、模型都正確；紅燈會寫原因（401＝Key 錯、404／410＝模型名稱已下架或網址錯、429＝被限流或額度用完）。
   - **B. 終端機**：`sudo docker exec clure-api /opt/venv/bin/python -m app.cli ai-test`（可加 `--provider gemini`）。
6. **開放給使用者**：每位使用者自己到「設定 → AI 設定」開啟（預設關閉）。

> 免費模型的名稱與限額常變動。測試回 404／410 時，到供應商網站挑一個目前可用的模型填進 `.env` 的 `CLURE_AI_*_MODEL`；Gemini 預設用 `gemini-flash-lite-latest` 別名，不怕舊型號下架。

## 接 NVIDIA（Nemotron 3.5 Super VL）

```
CLURE_AI_PROVIDERS=nvidia,gemini        # NVIDIA 優先、Gemini 備援（預設順序就是 nvidia,gemini,openrouter,custom）
CLURE_AI_NVIDIA_API_KEY=nvapi-你的Key
CLURE_AI_NVIDIA_MODEL=nvidia/nemotron-3.5-super-vl-120b-a12b   # 已是預設值，可省略
```
- Key 到 https://build.nvidia.com 登入後產生（`nvapi-` 開頭）。額度與限流以網站公告為準，**我沒有查到穩定的免費額度數字**；請把全站上限設在實際額度以內。
- 這是**推理模型**：預設會先輸出一長串思考。程式對 `nvidia` 的 `nemotron` 模型**自動帶 `chat_template_kwargs.enable_thinking=false`** 關掉思考；回應裡的 `<think>…</think>` 也會被去掉，content 為空（思考用完輸出長度）視為失敗、不扣額度。
- NVIDIA 官方建議取樣 `temperature=1.0`、`top_p=0.95`；本程式預設 `temperature=0`（結構化輸出較穩）。想照官方建議可設：
  `CLURE_AI_NVIDIA_EXTRA_BODY={"chat_template_kwargs":{"enable_thinking":false},"temperature":1.0,"top_p":0.95}`
  （`CLURE_AI_*_EXTRA_BODY` 適用所有供應商：JSON 物件，直接合併進請求本文；寫錯格式會被忽略並回到預設。）
- 驗證：`sudo docker exec clure-api /opt/venv/bin/python -m app.cli ai-test --provider nvidia`，或 AI 主控台「測試連線」（卡片會顯示額外參數名稱）。
- 拍照記帳需要視覺模型；VL 版本理論上支援 OpenAI 格式的 `image_url`，**我沒有實測**，若拍照辨識失敗，改讓 Gemini 排在前面。

## 免費額度要注意（Gemini）

- 限制以 **RPM（每分鐘請求）、TPM（每分鐘 token）、RPD（每日請求）** 計，任一項超過就 429；**按專案計，不是按 Key**。
- **每日額度在太平洋時間午夜重置**（約台灣下午 3 點，夏令結束後下午 4 點），與 Aster 的台北 00:00 不同。
- 官方文件沒有公布固定數字，**以 AI Studio 的 Rate limit 頁面為準**（會變動）。把 `CLURE_AI_GLOBAL_DAILY`、`CLURE_AI_GLOBAL_PER_MINUTE` 設在實際額度以內（預設 100 次／天、8 次／分）。
- 各功能都盡量省額度：規則先處理、結果快取、收據辨識才扣 2 點。額度緊的話，可以只開啟部分功能的使用者。

## 額度規則

- **一般使用者與管理員的額度分開計算**：各自有每日／每週／每月上限（預設一般使用者 30／120／400、管理員 60／300／1000），在「AI 主控台 → 開關與額度」分別設定；管理員用掉的不會佔用一般使用者的額度。**全站每日上限與每分鐘上限兩者合計**。AI 設定頁與主控台會標示你使用的是哪一組額度。

- 重置時間以 `CLURE_TIMEZONE`（預設 Asia/Taipei）：每日 00:00、每週一 00:00、每月 1 日 00:00。
- 每位使用者的日／週／月**任何一層**用完就擋（429，訊息指出哪一層與重置時間）；全站每日上限與**全站每分鐘上限**另外計算。
- 用量＝時間區間內 `ai_usage` 的 `cost` 加總，沒有會重置的計數器。呼叫前先「預留」，成功才保留；**供應商全部失敗、或回傳看不懂的內容時整列刪除，不扣額度**。
- 另有每位使用者每分鐘 10 次的頻率限制。

## 供應商鏈

`CLURE_AI_PROVIDERS` 依序嘗試（可用 `gemini`、`openrouter`、`nvidia`、`custom`）；HTTP 錯誤（含 429）、逾時、回應不是 JSON 都換下一家，同一家連續失敗 3 次冷卻 5 分鐘（記憶體內，重啟歸零）。沒設 Key 的自動略過。模型的 `max_tokens` 依任務給足（800–2200），避免新型模型的思考 token 吃掉輸出。

## AI 主控台（管理員）

「資安後台 → AI 主控台」（`/admin/ai`）每 30 秒自動更新：

- **整體狀態**、**供應商**（🟢正常／🔴最近失敗／🟠冷卻中／🔵尚未測試／⚪️未設定；模型、主機、Key 最後 4 碼、成功／失敗次數、最近成功與延遲、最近錯誤與原因、「測試連線」，測試成功會解除冷卻）。
- **用量**（今日／本週／本月、各供應商、一般使用者與管理員分開的合計、近 7 天長條圖）、**各使用者用量**（管理員以 🛡 標示）、**最近 20 次呼叫**（含功能：一句話記帳、問 AI、預算建議、白話解讀、整理分類、拍照記帳；不含內容）。
- **開關與額度**：AI 總開關、每人每日／每週／每月、全站每日上限。

連線狀況（成功／失敗次數、最近錯誤、冷卻）記在 API 程序的記憶體，**重啟會歸零**；用量與呼叫紀錄在資料庫。

## 操作助手（v4.0，`src/domain/agent/`、`src/services/agent.ts`、`src/features/home/AiChat.tsx`（`ChatPanel`，與首頁對話共用））

「AI 只規劃、本機預覽、你確認才寫入、可一鍵還原」：

1. **AI 規劃**：`/api/ai/agent-plan` 把一句話拆成最多 8 步，每步是白名單工具之一——`reclassify` 批次改分類、`set_budget` 建立／調整每月預算（含提醒門檻）、`add_recurring` 建立週期帳目（到期提醒你確認，不自動記帳；沒說分類時自動帶「訂閱」或「其他」並提醒）、`prepayment_sim` 貸款提前還款試算（只試算）、`add_rule` 建立自動分類規則（以後自動歸類，可與改分類串聯）、`add_goal` 建立存錢目標（算出平均每月要存多少）。沒有任何工具會刪帳目、動帳戶餘額或轉帳。
2. **本機預覽（Dry-Run）**：`domain/agent/plan.ts` 在記憶體的工作副本上依序模擬每一步（後面的步驟看得到前面的結果），算出受影響筆數、預算變化（本月已花、用掉幾 %、會不會超過提醒線）、帳戶餘額是否變動；一次最多改 500 筆，沒有篩選條件（會變成整本帳）、找不到分類、超過上限的步驟會被擋下並說明原因。
3. **原子執行**：`applyPlan` 在單一 Dexie 交易內寫入——任何一步失敗整批都不會寫入。
4. **一鍵還原**：每次執行記下「修改前的樣子」（存本機 `meta`，不同步，保留 7 天、最多 20 筆）；還原時逐筆確認「執行後沒被再改過」才動它，被你之後改過的略過並告知；寫回時間戳更新，其他裝置同步時也會跟著還原。
5. 首頁對話框偵測到「改歸類、設預算、建訂閱／週期、提前還款」這類說法（`domain/agent/intent.ts`，刻意保守），會引導到操作助手而不是當成記一筆。

## 動作圖譜與對話即介面（v4.1）

操作助手的工具從 6 個擴大到 12 個，**一句話可以跨帳目、轉帳、欠款、股票、目標一次做完**，仍是「AI 只規劃、本機預覽、確認才執行、整包可還原」：

- **新工具**：`add_transaction` 記一筆收支、`transfer` 帳戶間轉帳（轉進信用卡／貸款帳戶就是繳費／還款，貸款會附提前還款省下的利息試算）、`settle_debt` 結清欠款、`goal_deposit` 存入目標（同一份計畫剛建立的目標也能直接存入）、`buy_stock` 買進投資頁已有的台股標的（手續費依你的設定；沒說價格用最近報價試算並提醒）、`show_view` 在對話裡嵌入檢視卡。一份計畫最多 8 步。
- **預覽**：帳戶餘額的工作副本依序模擬（前一步的結果給後一步用），逐帳戶顯示「餘額 A → B」，會變負數時警告；擋下外幣帳戶（需要匯率，請用記帳面板）、投資頁沒有的標的、不存在的對象、未來日期。
- **執行與還原**：全部在同一個 Dexie 交易（帳目、轉帳、帳戶餘額、欠款、股票交易、目標…）——任何一步失敗整批回滾；整包計畫共用一筆還原紀錄，還原時記帳／轉帳／交易走各自的刪除流程，帳戶餘額跟著回復（`tests/unit/agent-actions.test.ts`）。
- **送給 AI 的內容多了**：欠款對象、進行中目標、投資頁標的代號的**名稱**（只送名稱，不送金額、股數或成本）。
- **對話即介面（Generative UI）**：財務自由（蒙地卡羅＋退休年齡／每年可存兩根拉桿）、稅務規劃（除息前預警、海外所得）、現金流預測、花費分析，直接嵌在對話裡。**這些全部是本機運算、不用 AI、不扣額度**：對話框的「📊」快捷鈕、或直接說「財務自由」「現金流」「如果 55 歲退休」「上個月花費」就會出卡；AI 計畫裡的 `show_view` 步驟則在確認執行後依新資料重算（`features/ai/views/`）。
- **靈動島全域 AI**：中央圓球在任何頁面**往上滑**，或在非記帳頁**長按**，都會叫出同一個對話；對話知道你正在看哪個畫面——「📍 目前畫面」標籤附上一句摘要（帳戶名與餘額、投資總市值與損益、報表期間與收支合計、規劃分頁），**只有名稱與統計數字**，只在送去 AI 的問題（操作助手、問 AI）才附上，標籤一點就取消，內容可在「查看送出過什麼」檢查。一切都是手動觸發，不會自動呼叫 AI（額度由你決定）。
