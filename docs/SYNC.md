# 跨裝置同步

同一個帳號在手機、平板、電腦之間自動同步帳目與設定。資料存在每台裝置的 IndexedDB（離線可用），並同步到你自架的後端（NAS）。

## 同步範圍

| 會同步 | 不同步（只留在該裝置） |
|---|---|
| 帳戶（含貸款攤還資訊）、分類、帳目、轉帳、範本、預算、專案、標籤、常用篩選、週期帳目、分期、分帳對象與應收應付、存錢目標、匯率（含手動覆蓋）、股票、交易紀錄、股利、觀察清單、淨資產快照、心願清單、自動分類規則、設定（含匯入格式、財務自由與稅務假設） | 收據照片（體積大）、App 鎖 PIN／Face ID、通知與背景推播設定、文字大小、上次使用的帳戶、月曆收合狀態、報價快取、端對端加密金鑰、同步游標與裝置 id（`meta`） |

備份檔（JSON）也不包含 `meta` 與 `sync_outbox`，還原時保留這台裝置的同步狀態與裝置專屬設定（App 鎖、Face ID、通知），避免把別台裝置的裝置 id／游標帶過來而漏同步。

## 流程

```
本機寫入 ──(DBCore 中介層，同一個交易)──▶ sync_outbox（待上傳佇列）
                                              │ 約 1 秒後
                                              ▼
                                   POST /api/sync/push ──▶ sync_records（最後寫入者勝）
其他裝置 ◀── GET /api/sync/pull?since=游標 ◀────────────────┘
```

1. **變更追蹤**（`src/db/sync-tracking.ts`）：Dexie DBCore 中介層攔截所有寫入（`add`／`put`／`update`／`modify`／`delete`／`clear`，含 bulk），在同一個 IndexedDB 交易中寫入 `sync_outbox`：`{ id: 表名|主鍵, table, key, at: 變更時間 }`。同一筆多次修改只保留最後一次。
2. **上傳**：讀取佇列，附上每筆資料「當下」的完整內容（讀不到＝已刪除），每批最多 400 筆／約 1.5 MB。伺服器只採用比現有版本更新的（`updated_at` 較大）；未採用的回傳伺服器版本，前端直接套用。上傳期間又被修改的項目保留到下一輪。
3. **下載**：以伺服器游標（每位使用者遞增的 `seq`）取回其他裝置的變更。若本機有更新、尚未上傳的版本則保留本機。
4. **套用**：在標記為「遠端」的交易中寫入（不會再進佇列，避免循環）；涉及帳目／轉帳／帳戶時重算帳戶餘額（餘額是快取，每台裝置自行由帳目算出）；設定有變更則立即重新載入。

## 首次同步（新裝置、或既有裝置第一次更新到同步版本）

1. 先把這台裝置既有的資料排入佇列：**沒修改過的預設資料（內建分類、設定）變更時間記為 0**，修改過的以修改時間為準。
2. **先下載再上傳**：伺服器已有的版本一律優先於這台裝置的預設值。新裝置登入後直接拿到其他裝置的帳目、分類與設定，不會再出現首次設定畫面。
3. 預設分類只在資料庫完全空白時建立（`bootstrap.ts`），之後只補上程式需要的系統分類。被使用者刪除的預設分類不會再跑回來。

## 同步時機

登入後立即（進入 App 前最多等 20 秒，顯示「正在同步你的帳目…」）、本機變更後約 1 秒、畫面可見時每 15 秒、在背景時每 60 秒、切回 App／切到背景、恢復網路、登出前。

## 衝突處理

- 以「變更時間」做**最後寫入者勝**，單位是整筆資料。同一筆在兩台裝置都被修改時，較晚的修改勝出。
- 時間相同時保留伺服器既有版本。
- **時鐘校正**：`/api/sync/status` 回傳 `server_time`，前端以「請求往返的中點」算出本機與伺服器的時差（誤差 2 秒內視為準確），之後所有變更時間都以伺服器時間記錄（`syncClock()`）。伺服器另外把超過「現在 + 5 分鐘」的變更時間截為現在，避免時鐘偏快的裝置永遠蓋掉其他裝置。

## 墓碑清除與完整重新同步

- 刪除會在伺服器留下「墓碑」（`deleted = true`）。墓碑保留 90 天後清除（上傳時每位使用者每 6 小時檢查一次），並在 `sync_states.purged_seq` 記下清除點。
- 游標早於清除點的裝置（超過 90 天沒開），下載時會收到 `reset: true`：前端改為從頭下載伺服器上目前存在的全部資料，並刪除「本機有、伺服器沒有、也不在待上傳佇列」的資料，再重算餘額。

## 端對端加密（選用）

設定 → 帳號 → 端對端加密。

- 加密密碼（與登入密碼分開）→ PBKDF2-SHA256 310,000 次 ＋ 伺服器保存的隨機鹽 → AES-256-GCM 金鑰；金鑰以**不可匯出**的 `CryptoKey` 存在這台裝置的 IndexedDB `meta`。
- 上傳的 `payload` 變成 `{ "$enc": 1, "iv": …, "ct": … }`；伺服器只看得到資料表名稱、資料 id、修改時間與是否刪除。
- 伺服器 `sync_keys` 只存鹽、次數、驗證用密文（以金鑰加密的固定字串）與版本號。新裝置登入後同步會暫停（狀態「需要輸入加密密碼」），輸入正確密碼後才下載。
- 啟用／更換／停用時會先同步一次，再把所有資料以新格式重新上傳；其他裝置的版本號不符時會要求重新輸入密碼。
- **忘記加密密碼無法從伺服器取回資料**；已解鎖的裝置仍有完整明文，可停用後重新上傳。
- 解密在 IndexedDB 交易之外進行（WebCrypto 的 await 會讓交易提早結束）。

## 後端

| 項目 | 說明 |
|---|---|
| 資料表 | `sync_records(user_id, table_name, record_key, updated_at, deleted, payload JSON, seq, device_id)`，`(user_id, table_name, record_key)` 唯一；`sync_states(user_id, last_seq)` |
| 遷移 | `0002_sync.py`、`0003_purge_ratelimit.py`（墓碑清除點）、`0004_e2ee_push.py`（加密設定、推播）；後端啟動（含熱重載）時自動套用 |
| 序號 | 先 `UPDATE sync_states` 取得寫入鎖再配發 `seq`，同一使用者的上傳依序提交，下載不會漏資料 |
| 端點 | `GET /api/sync/status`（含 `server_time`、`purged_seq`、`e2ee`）、`POST /api/sync/push`（需 CSRF）、`GET /api/sync/pull?since=&limit=&device_id=`（可能回 `reset`）、`GET`／`PUT /api/sync/keys` |
| 限制 | 只接受白名單資料表；單筆 ≤ 256 KB；每批 ≤ 500 筆；每位使用者 ≤ 50 萬筆 |
| 隔離 | 所有查詢都以登入者 `user_id` 限定；刪除使用者時同步資料一併刪除（ON DELETE CASCADE） |
| 隱私 | 未啟用端對端加密時，帳目以明文 JSON 存在你自己的伺服器資料庫；請保護好 NAS 與備份檔，或啟用端對端加密。 |

伺服器資料被清空、或換了一台伺服器時，前端偵測到游標倒退，會自動重新完整上傳。

## 效能

- 上傳時依資料表批次讀取（`bulkGet`），套用下載時批次讀取待上傳佇列。
- 輪詢時若伺服器游標沒變、本機也沒有待上傳的變更，只發出一個 `status` 請求。

## 測試

- `tests/unit/sync-tracking.test.ts`：各種寫入都會進佇列、裝置專屬設定與遠端套用不會。
- `tests/unit/sync-engine.test.ts`：兩台裝置透過模擬伺服器同步，涵蓋新裝置取得全部資料且預設值不覆蓋修改、雙向新增／刪除與餘額重算、同一筆衝突、備份還原不帶入同步狀態、墓碑清除後完整重新同步、時鐘校正、端對端加密。
- `server/tests/test_sync.py`：上傳／下載、最後寫入者勝、刪除、使用者隔離、驗證、分頁、刪除使用者、時鐘截斷、墓碑清除與 reset。
- `server/tests/test_push_e2ee.py`：加密設定、推播加密格式（以瀏覽器端演算法解密驗證）、訂閱網址白名單、排程與發送。
